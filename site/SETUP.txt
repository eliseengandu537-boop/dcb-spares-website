DCB SPARES WEBSITE

Next.js App Router, TypeScript, Tailwind CSS, Framer Motion.

Local development
  npm ci
  npm run dev -- --port 3001

Production
  npm run lint
  npm run typecheck
  npm run build
  npm run preview

Run these commands from the site/ directory.
The production build is written to .next/. Preview runs the Next.js Node
server at http://127.0.0.1:3001, including the quote submission endpoint.
Automatic email requires this server runtime; static-only hosting cannot
run it. Any existing out/ directory is an older static export and does not
contain the current quote service.

Browser checks
  Start npm run preview, then npm test in another terminal.
  Tests use installed Google Chrome, at desktop and mobile sizes.
  npm run dev may use a different port if 3000 is occupied; the test
  configuration and screenshot script expect 3001.

DCB Assist
  The floating widget provides catalogue search, branch information,
  quote guidance and a visitor-initiated WhatsApp link.
  It uses predefined replies and local catalogue matching, not an AI model.
  These guided replies need no AI API key or model installation.
  Chat history stays in page memory and can be cleared with the reset button.
  npm run dev/build refreshes public/assistant-catalogue.json automatically.
  The quote form asks what the customer needs, then their name, email,
  phone, province/region and town/city (plus company, if applicable).
  Vehicle make/model are optional.
  A customer can add one JPG, PNG or WebP photo (up to 10 MB). The browser
  prepares a smaller JPEG locally; the server validates and re-encodes it
  without embedded metadata. Uploads are bounded to 3 MB and sent as email
  attachments, not stored in a public gallery. The review shows the photo.
  WhatsApp/email fallback links cannot include attachments; customers are
  reminded to attach the photo manually in their messaging or email app.
  Gary@dcbspares.co.za receives every quote. If the customer's area has an
  assigned representative, that representative is the To recipient and Gary
  is CC'd on the same email. Otherwise Gary is the sole To recipient and
  coordinates assignment manually. A quote never broadcasts to all reps.
  The email fallback follows the same recipient rules.
  The customer's email is the Reply-To address. Recipient addresses are
  resolved from trusted DCB assignments, not visitor-supplied email addresses.

Area routing
  src/lib/quote-routing.ts contains quoteTerritories and the region options.
  DCB's confirmed territories are:
    Shane: Western Cape, Northern Cape, Eastern Cape.
    Hans: KwaZulu-Natal, Mpumalanga, Limpopo.
    Sean: Gauteng, Free State, North West.
  The area rep is the To recipient and Gary is always CC'd.
  Unassigned areas, "Not sure", and older forms without a region go to Gary.
  Do not infer territories from branch addresses or email names. Update this
  map only from DCB's confirmed list, then rebuild and deploy the website.
  Tests check this confirmed map as well as test-only routing fixtures.

Google email setup (Gmail or Google Workspace)
  The recipient list does not authorise sending. One authorised Google
  sending account and its app password (or OAuth connection) are required.
  The sender can be a personal Gmail account authorised by the website owner;
  the sales recipients remain the assigned DCB representative with Gary CC'd.
  DCB's public MX record points to Microsoft 365. That does not prevent
  sending from an authorised Gmail account to DCB's Outlook mailboxes.
  site/.env.local is ready for your local settings and is ignored by Git.
  If starting a fresh checkout, copy .env.example to .env.local first.
  Keep credentials out of chat and source control.

  Configure the Google account used to send the quotes:
    GMAIL_USER=your-authorised-sending-address@gmail.com
    GMAIL_APP_PASSWORD=your-Google-app-password

  Use an app password, not the mailbox's normal password. App passwords
  require 2-Step Verification and must be allowed for that Google account.
  Create one at https://myaccount.google.com/apppasswords using the sender's
  Google account, with a label such as "DCB Website". Keep it out of chat.
  Alternatively, leave GMAIL_APP_PASSWORD blank and set all three:
    GMAIL_CLIENT_ID
    GMAIL_CLIENT_SECRET
    GMAIL_REFRESH_TOKEN
  OAuth credentials must authorise GMAIL_USER for the Gmail SMTP scope
  https://mail.google.com/. The refresh token needs offline access.
  SMTP uses smtp.gmail.com on port 465 with TLS.
  Reference: https://nodemailer.com/smtp/oauth2

  After saving .env.local, restart npm run preview (or the dev server).
  These are server-only settings; never add a NEXT_PUBLIC_ prefix.

Live website email setup (Vercel)
  .env.local configures localhost only; Git does not publish its values.
  In Vercel, select the project named "site", which serves dcbspares.co.za.
  Open Settings > Environment Variables and select Production.
  Add the same GMAIL_USER and GMAIL_APP_PASSWORD values, or the complete
  OAuth connection described above. Keep credentials private and use
  Vercel's sensitive/secret setting for passwords and tokens.
  Save, then redeploy the Production deployment. Existing deployments do
  not receive newly added environment variables automatically.
  Settings: https://vercel.com/eliseengandu537-boops-projects/site/settings/environment-variables
  Documentation: https://vercel.com/docs/environment-variables/managing-environment-variables
  If the form says "Online submission is not connected yet", the running
  deployment does not have a usable sending configuration. Check the correct
  project, Production scope, sending address, auth fields and redeployment.
  A code push alone cannot supply missing mailbox credentials.

Delivery verification
  No live email was sent during development verification. Once configured,
  submit an intentional test quote and confirm receipt in Gary's inbox and
  the assigned rep's inbox, if that area has an assigned rep.
  The website confirms submission only after SMTP accepts all recipients;
  mailbox delivery or spam filtering still needs that inbox check.

  If email is unconfigured or fails, the form retains entered details and
  offers WhatsApp and a prefilled email for the visitor to send manually.
  It does not claim successful submission when sending is unconfirmed.
  The server validates and limits requests, rejects cross-origin browser
  submissions and deduplicates retries for ten minutes. Limits and retry
  records are in memory for one Node process and reset on restart. A future
  deployment with multiple instances needs shared rate-limit/retry storage.
  There is no customer database or application logging of quote contents.
  Submitted messages are retained in the relevant email mailboxes.

Scroll-controlled alternator
  The homepage uses a locally generated Three.js assembly. Scroll down to
  separate six components; scroll up to reassemble them. Component buttons
  explain each part. The model is illustrative, not a service drawing.
  On every screen size, the hero scrolls with the page while the model
  opens. No pinned animation needs to finish before browsing further.
  Tap "Inside the alternator" to open the optional component explanations.
  Reduced motion and unavailable WebGL use the original photograph.
  The renderer only draws while scroll progress or viewport size changes.
  src/components/exploded-alternator.tsx controls the interaction.
  src/lib/alternator-scene.ts builds and renders the model.
  artifacts/alternator-open-close.webm is the rendered video preview.
  With the local preview running, regenerate it using:
    node scripts/render-alternator-video.mjs
  Set PLAYWRIGHT_BASE_URL to preview a different local port.

Content and contacts
  src/lib/data.ts holds all sixteen product ranges and branch contacts.
  src/data/products.json holds imported individual products, original
  specifications, gallery images, part numbers and category memberships.
  src/data/catalogue.json records source category and vehicle-brand counts.
  src/data/company.json contains the original company-page text.
  src/data/original-assets.json maps source photographs to local files.

Enquiries
  The contact-page and product WhatsApp enquiries prepare messages for
  visitors to review and send themselves. They use +27 83 630 3818.
  Email links open the visitor's email application. DCB Assist additionally
  offers automatic email submission once Workspace is configured above.

Brand wording
  DCB is described as the primary distributor of GB products.
  Vehicle makes and OE references describe aftermarket compatibility.
  They do not identify vehicle makers' branded parts supplied by DCB.
  Shared business statements and sales contacts are in src/lib/business.ts.

Catalogue
  The complete current public catalogue is imported from dcbspares.co.za.
  Products have local detail pages, photograph galleries, specifications
  and WhatsApp enquiries. Search matches names, SKUs and OE references.
  Browse by category or vehicle brand, sort results and paginate locally.
  Run node scripts/verify-catalogue.mjs to check source counts and images.
  The verifier's --export mode applies only to historical static exports;
  use the production build and browser tests for the current Node version.
  The source does not publish current prices, stock or online checkout.
  Customers confirm those with DCB. This is a catalogue snapshot, not a
  live inventory connection. Source import tooling and cached responses
  are retained in ../.migration-tools/ for follow-up imports.
  Original /category/, /brands/category/, /brands/product/, /about-us/
  and /contact-us/ routes remain available alongside the new navigation.

Assets
  Original DCB photography, category artwork and brand logos are stored
  locally as compressed WebP. The original site logo is recovered from
  its public cached image because its primary image URL returns 404.
  The complete supplied 2026 company profile is available at
  /company-profile/ and public/documents/dcb-company-profile-2026.pdf.
  Fonts are self-hosted. See asset-provenance.json for import evidence.
